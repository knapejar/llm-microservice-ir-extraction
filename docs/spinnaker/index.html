Spinnaker: inbound endpoints by extractor

Ten services of spinnaker/spinnaker at commit . Part of a master's thesis comparing LLM-based extraction of microservice endpoints with CIMET. Code: knapejar/llm-microservice-ir-extraction.

  • DeepSeek-V4.1-Flash and GLM-5.3-Flash: the agent of experiment 02 (agent_extract.py, tag agent-2026-10-26). The model explores one service with read-only tools and records endpoints; each entry must cite the line of its route declaration verbatim, or it is rejected.
  • Opus 5.5: the same task prompt, tools and validation (agent_cli.py), with the model driving the loop itself instead of being called over an API.
  • CIMET: the main branch of the extraction library, run on the whole repository. It detects three microservices (kayenta, echo-web, spin), so the other services have no CIMET output. An extended CIMET build, not public yet, reports 894 endpoints for Spinnaker; its per-endpoint output is not included.

An endpoint is a service, a verb and a route with placeholders reduced to {}. ANY is a mapping without a method. Rows where the extractors that ran on the service disagree are highlighted; the disagreements were checked by hand against the source, and the review column gives the verdict.
