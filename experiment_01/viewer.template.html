Status glossary

match
Equal to a ground-truth entry at the selected level (M2: service + verb + normalized path). The GT id column names the entry.
missed
Ground-truth entry the source did not report; the row shows the ground-truth values.
wrong route
Right handler (M4 class + method) but a route (M2) the ground truth does not have.
near miss
Same M2 route or M4 handler as a ground-truth entry, but not equal at the selected level (e.g. M1 notation {?} vs {id}). Never occurs at M2.
duplicate
Key already matched: the source reports the same entry more than once. Counts as a false positive.
role-separation
Reported as inbound, but it is a ground-truth outbound call (e.g. a Feign client method).
hallucination
Reported as inbound; matches nothing in the ground truth, inbound or outbound.
extra
Outbound call not in the ground truth.
outside frame
Outside the part of the system the ground truth covers; not scored.

Matching levels

When does a reported entry count as the same as a ground-truth entry? Pick the level in the header; statuses and scores follow it.

M1 exact
service + HTTP verb + path exactly as written. Strictest: /movie/{?} ≠ /movie/{movieId}. Measures notation compatibility more than detection.
M2 normalized ⭐
service + HTTP verb + normalized path: placeholders collapse to {}, ${prop:default} resolves to its default, query string, host and trailing slash are dropped, case is folded. The operative level reported in the results.
M3 path only
service + normalized path; the HTTP verb is ignored. Shows whether a miss at M2 is only a wrong verb.
M4 code
service + class + method (a leading underscore is ignored). Compares where the handler is in the code, not the URL; shows whether a miss at M2 is only a wrongly composed path.
